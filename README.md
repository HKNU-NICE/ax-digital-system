# AX 디지털시스템 강의실 — 15주 전체

15주가 **같은 틀** 위에 올라가 있습니다. 주차마다 다른 것은 설정 파일
`assets/weeks/wNN.js` **하나뿐**이고, 나머지(화면 구성 · 채점 · 제출 · 보고서)는
`assets/week.js` 엔진이 전부 맡습니다.

**과제는 전부 강의 교안의 「과제」 슬라이드에서 그대로 가져왔습니다.** 교안이 기준이고

### 왜 이렇게 나누나

실습실에만 있는 것은 **보드**입니다. Quartus 와 ModelSim 은 학생 노트북에도 깔리므로,
보드가 있어야 하는 일만 수업 중에 몰고 나머지를 앞뒤로 나눴습니다.

예습의 핵심은 **답을 미리 적어 두는 것**입니다. 학번에서 뽑은 `a`, `b`, `cin` 으로
합·자리올림·캐리 사슬을 손으로 계산해 적게 하고, **정답은 보여 주지 않습니다.**
수업 중에 직접 돌려서 맞춰 보는 순간이 이 설계의 알맹이입니다 —
틀렸으면 "왜 틀렸는지" 를 적는 칸이 열립니다.

### 별도 보고서 문서는 없습니다

과목 표준 제출물 ① RTL view ② VHDL code ③ 시뮬레이션 파형 ④ 동작 설명을
모두 사이트에서 받으므로, 학생이 따로 작성할 한글/워드 보고서가 없습니다.
제출 직전 체크리스트가 여덟 항목의 준비 상태를 보여 줍니다.

보드 시연 조합은 **학번마다 다릅니다.** 사진을 돌려써도 지정된 스위치 위치가 달라 맞지 않습니다.

### 실습을 실제로 했는지 확인하는 방법

실습은 코드를 전부 주므로, 파형만 보고 자가점검을 맞힐 수 있습니다. 그래서 **4단계**를 두었습니다.

- 학생이 1단계의 `adder4.vhd` 를 **직접 입력**해 사이트에서 실행합니다.
- GitHub Actions 가 512가지 전수검사를 돌리고, 결과가 **학번·시각과 함께 `실행기록` 시트에 남습니다.**
  이 기록은 페이지에서 만들 수 없습니다 — 서버가 쓰는 값입니다.
- 추가로 본인 ModelSim 화면 1장을 받습니다.

세 가지가 겹칩니다. 자가점검은 **학번마다 묻는 시각이 달라** 답을 돌려쓸 수 없고,
실행 기록은 **위조가 불가능하며**, 캡처는 교수님이 눈으로 거릅니다.
캡처 한 장만으로 판정하지 않는 것이 요점입니다.

## 1. 사이트 올리기 (5분)

1. GitHub 에 저장소를 새로 만듭니다 (예: `vhdl-class`).
2. 이 폴더의 내용을 그대로 올립니다.
3. Settings → Pages → Source 를 `main` 브랜치 `/ (root)` 로 지정합니다.
4. 몇 분 뒤 `https://<계정>.github.io/vhdl-class/` 에서 열립니다.

이 단계만 해도 교안·파형·자가점검은 전부 동작합니다. 제출만 아직 안 됩니다.

## 2. 제출 받기 (15분)

1. [script.google.com](https://script.google.com) 에서 새 프로젝트를 만들고
   `apps-script/Code.gs` 내용을 붙여넣습니다.
   파일을 하나 더 만들어 `apps-script/Report.gs` 도 붙여넣습니다 (보고서 PDF 생성).
2. 맨 위 `SECRET` 을 임의의 값으로 바꿉니다.
3. **배포 → 새 배포 → 웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
4. 나온 `/exec` 주소를 복사해 `config.js` 의 `ENDPOINT` 에 넣고,
   `SECRET` 도 같은 값으로 맞춥니다.
5. 다시 올리면 제출이 교수님 드라이브 폴더와 시트에 쌓입니다.

> `ENDPOINT` 가 비어 있으면 제출 버튼이 **파일 저장**으로 동작합니다.
> 학습관리시스템으로 받으실 거면 이 상태로 두셔도 됩니다.

시트 열 구성: 제출시각 · 학기 · 실습 · **단계** · 학번 · 이름 ·
개념확인 · 예측입력 · 코드읽기 · 질문 · 실습실행 · **예측대조** · 자가점검 · 코드실행 ·
qsf통과 · Quartus통과 · Errors · Latch · Registers · Pins · 보드통과 · 보드조합 ·
동작설명 · 토의 · 자기채점 · **보고서PDF** · 첨부파일 · **교수점수 · 코멘트**

첫 배포 뒤 시트를 한 번 열면 **VHDL 강의실** 메뉴가 생깁니다 — 보고서를 다시 만들 수 있습니다.

첫 배포 뒤 시트를 한 번 열면 **VHDL 강의실** 메뉴가 생깁니다.

## 3. 사이트에서 코드 실행하기 (선택 · 30분)

학생이 페이지에서 VHDL 을 타이핑하고 **GHDL 로 실행** 을 누르면
1~2분 뒤 PASS/FAIL 과 GHDL 오류 메시지가 돌아옵니다.
브라우저 안에서 도는 것이 아니라 **GitHub Actions 를 실행기로 빌려 쓰는** 방식이며,
학생은 GitHub 계정도 git 도 필요 없습니다.

```
학생 페이지 ──POST──▶ Apps Script ──GitHub API──▶ Actions (GHDL)
     ▲                     ▲                           │
     └──3초마다 상태 조회───┴────────결과 회신──────────┘
```

**① GitHub 토큰 만들기**
Settings → Developer settings → Personal access tokens → Fine-grained
- Repository access : 이 저장소 하나만
- Permissions : **Actions = Read and write** (이것 하나면 충분합니다)

**② Apps Script 속성 채우기**
프로젝트 설정 → 스크립트 속성에 네 개를 넣습니다.

| 이름 | 값 |
|---|---|
| `SECRET` | config.js 의 SECRET 과 동일 |
| `CALLBACK_SECRET` | 임의의 값 (아래 ③ 과 동일하게) |
| `GH_TOKEN` | ① 에서 만든 토큰 |
| `GH_REPO` | `계정/저장소` 예: `hknu-ysyu/vhdl-class` |

**③ GitHub 저장소 Secrets**
Settings → Secrets and variables → Actions
- `CALLBACK_URL` : Apps Script 의 `/exec` 주소
- `CALLBACK_SECRET` : ② 와 같은 값

**안전장치** — 이미 들어 있습니다.
- 학번당 **시간당 20회** 까지만 실행
- 코드 20 KB 제한, 작업 **5분** 타임아웃, 시뮬레이션 `--stop-time=10us`
  (무한 루프 제출로 Actions 분을 태울 수 없습니다)
- 학생 코드는 base64 로 전달 후 파일로 복원 — 셸에 끼어들 수 없습니다
- GitHub 토큰은 Apps Script 안에만 있고 학생에게 노출되지 않습니다

**비용** — 저장소를 public 으로 두면 Actions 분이 무제한입니다.
private 이면 교육용 Team 월 3,000분을 쓰며, 1회 실행이 약 1.5~2분입니다.
Settings → Billing 에서 한도를 **$0.00** 으로 걸어 두세요.

### 실행 워크플로에 주차 추가

`.github/workflows/run-vhdl.yml` 의 표가 주차와 채점기를 잇습니다. 이 표는
**손으로 고치지 말고** 설정 파일에서 다시 만드세요 — 표와 설정이 어긋나면
학생 화면과 서버 채점이 다른 것을 검사하게 됩니다.

```bash
node gen_workflow.js      # assets/weeks/*.js 의 localCmd 만 보고 표를 다시 만든다
node verify_tasks.js      # 주차별 정답본은 PASS, 골격은 FAIL 인지 확인
```

표의 한 줄은 이런 모양입니다 (`RUNARGS` 가 주차마다 다릅니다 — 11주차 과제는 2 ms 가 필요합니다).

```bash
lab05p) WK=w06; TOP=reg8;            TB=tb_reg8_check;           DEPS=""; RUNARGS="--ieee-asserts=disable --stop-time=20us" ;;
lab05)  WK=w06; TOP=shift_reg8_rot;  TB=tb_shift_reg8_rot_check; DEPS=""; RUNARGS="--ieee-asserts=disable --stop-time=20us" ;;
```

## 교안과의 일치 (중요)

사이트 코드는 **강의 슬라이드의 규약을 그대로** 따라야 합니다. 확인한 사실:

| | 교안 | 비고 |
|---|---|---|
| 부품 연결 | `u : entity work.이름 port map (...)` | **`component` 선언은 과목 전체에서 쓰지 않음** (3주차부터 이 방식) |
| full_adder 포트 | `a, b, cin, s, cout` | 5주차에 처음 등장 — 그 전 주차에는 없음 |
| addsub4 포트 | `a, b, sub, r, c, v` | 플래그 이름이 **C / V** — 과제 `addsub8` 도 같은 이름 |
| 반복 | `for ... generate` | 5주차 교안에서 도입 |
| 핀 배정 | 각 주차 `.qsf` 를 그대로 읽어 `assets/pinmaps.js` 로 만듦 | 핀 번호를 손으로 적지 않음 |

주차를 추가할 때 해당 주차 PDF 에서 포트 이름과 구문 스타일을 먼저 확인하세요.

```bash
pdftotext -layout W05_산술회로.pdf - | grep -i "port map\|entity\|component"
```

## 설계 메모

- **합성 점검이 들어 있습니다.** 실행 워크플로가 `ghdl --synth` 로 래치와 비합성 구문을 먼저 잡습니다.
  Quartus 에 올리기 전에 같은 오류를 미리 보여 주므로 실습 시간의 "왜 안 돼요" 가 크게 줍니다.
- **페이지에 실리는 코드는 전부 컴파일되는 VHDL 이어야 합니다.** 문법을 가르치는
  과목이라 학생은 화면의 코드를 그대로 따라 칩니다. 1단계의 골격은
  `ghdl -a` 와 `ghdl -e` 를 통과하도록 확인했습니다 (출력 미연결이라 파형은 `U`).
  생략은 `...` 로 쓰지 말고 반드시 VHDL 주석(`--`) 안에 두세요.

- **자가점검 정답은 페이지에 없습니다.** 매번 `lab04.vcd` 를 읽어 계산합니다.
  소스를 열어도 정답이 나오지 않고, 학번으로 문항이 달라집니다.
  시험 벡터 16개 기준 **906가지 조합**, 30명 반에서 답이 겹치는 학생은 평균 0.7명입니다
  (벡터 6개였을 때는 9명이었습니다 — `tb_addsub4.vhd` 의 벡터를 늘리면 더 줄어듭니다).
- **개념 체크는 점수가 아닙니다.** 빠진 개념을 알려 주는 용도이며, 단어만 넣어도 통과합니다.
  실제 점수는 시트의 교수님 채점란에서 매깁니다.
- **모범답안은 학생이 30자 이상 쓴 뒤에만 열립니다.** 자기 글과 대조하게 하려는 장치입니다.
- 작성 중 내용은 브라우저에 자동 저장되어, 실수로 닫아도 이어서 쓸 수 있습니다.
